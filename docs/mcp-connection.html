Authorized MCP connection

Architecture boundary

The dashboard is a public browser/PWA interface. It does not inherit the ChatGPT connector's OAuth bearer token, grant device permissions, or execute native commands.

LeeWay Runtime Fabric owns authenticated ingress; the existing Device Bridge handles authorized device discovery. The current issuer direction is ZITADEL, but live issuer, audience, owner subject and scope must be verified against the deployed resource metadata—not copied from this page.

Read-only qualification sequence

  1. Verify /.well-known/oauth-protected-resource/mcp for the actual resource.
  2. Authorize an approved MCP client for the exact resource, runtime read scope and device discovery scope.
  3. Run runtime_health, then bridge_devices, and only then bridge_capabilities for a returned owner-scoped device.
  4. Confirm physical connectivity separately from configured device identity; require per-command admission before enabling controls.

A public GitHub/Vercel page is not proof that a physical computer, phone or automation engine is running.

Known limitation

At the November 3, 2026 read-only check, runtime_health returned AVAILABLE with OIDC token verified, while bridge_devices returned LEEWAY_BRIDGE_DISCOVERY_HTTP_502. This is a dated observation, not an ongoing health feed.
