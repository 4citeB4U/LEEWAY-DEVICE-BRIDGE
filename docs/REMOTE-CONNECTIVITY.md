# Remote Connectivity Contract\n\n## Purpose\n\nThe LeeWay Device Bridge must remain reachable after the development PC and USB cable are removed.\n\n## Authority split\n\n- GitHub Pages: canonical public configuration, packages, contracts, relay URL, public identity registry.\n- Phone runtime: device identity, owner authority, Formula gate, execution, local receipts.\n- Relay: transport only. It may route authenticated envelopes but may not become execution authority.\n- LLM/controller: replaceable client with an authorized signing key.\n\n## Live path\n\nAuthorized controller / LLM -> signed WSS challenge -> transport relay -> phone outbound foreground connection -> LocalAuthority -> LW-F8 gate -> normalized capability -> real phone/provider/model execution -> receipt -> relay -> controller.\n\nThe phone initiates the Internet connection. No inbound port, PC, Docker runtime, or USB cable is required after installation/configuration.\n\n## Security\n\nDevice authentication uses the existing Android Keystore P-256 private key. Only the public SPKI key is published through GitHub Pages. Controllers use separate P-256 identities. Challenge signatures use SHA-256 with ECDSA.\n\n## Owner stop\n\nSTOP AGENT ACCESS remains authoritative. A connected relay does not imply that commands are executable.\n\n## Current acceptance gate\n\nSource present != deployed != connected != authenticated != remote execution verified. Production status may only be promoted after a signed command traverses the relay with USB disconnected and a physical phone receipt returns.
